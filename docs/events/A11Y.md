# Speech Events: accessibility and keyboard pass

This page records the axe and keyboard check that docs/events/DESIGN.md §6 asks for before a build. It covers every Speech Events
screen except Congress. Congress has its own pass.

## Method

- **Tool.** axe-core **4.10.2**, pinned. It is installed only into `events/tools/a11y/.deps/`, which git ignores. The
  app never loads axe.
- **Browser.** Playwright's Chromium, the copy already on the machine. The runner serves the repo root on 127.0.0.1 and
  opens `/events/`. Each screen starts from an empty device, and the runner reaches it with clicks, keys and direct
  links (the page address).
- **Rules.** WCAG 2.2 A and AA (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`) plus axe best practices.
- **Pass rule.** A screen passes when it has no serious or critical violation, no page error, and does not scroll
  sideways. Moderate and minor items are listed below.
- **Self-check.** Before every run, axe has to find a known fault (an image with no text). If it does not, the run
  stops. A "0 violations" result therefore means axe really ran.
- **Opt-in.** The runner needs a browser, so it is not part of `node --test`. Its pure parts (the screen list, the
  matrix, the summary) are tested in `events/a11y-runner.test.mjs`.

Run it from the repo root:

```
npm install --prefix events/tools/a11y/.deps axe-core@4.10.2 --no-save --no-package-lock   # once
node events/tools/a11y/run.mjs              # every screen, light and dark, 390 x 844 and 1366 x 768
node events/tools/a11y/run.mjs --sizes=narrow   # 360 x 740
node events/tools/a11y/run.mjs --only=rank,type --shots --table
node events/tools/a11y/keys.mjs             # keyboard walk at laptop size; add --phone for 390 x 844
```

Results go to `events/tools/a11y/out/`, which git ignores.

### Still listed (moderate, not fixed)

- **Print sheet: `landmark-one-main` and `region`.** The run uses print media, which hides `<main>` and shows only the
  print sheet. The sheet is made for paper or PDF, not for a screen reader, and the screen view behind it passes. A fix
  would mean changing the shared print sheet in core/, so it is left for the core owner.

### Open items for the core owner (core/ui.js, not changed here)

The Congress pass found these two toast issues. Both live in the shared core/ui.js toast code, which this pass may
not change.

- **Toast Undo is the last Tab stop.** After a delete, a keyboard user has to Tab through the whole page to reach Undo
  before the toast times out.
- **Esc does not close a toast.**

## Keyboard walk

Method: `node events/tools/a11y/keys.mjs`, run at 1366 × 768 and at 390 × 844. For one room of each family (OO, POI,
Duo, USX, IMP) it goes: My day → Start a round → search the picker → confirm sheet → setup (paste) → room → time each
speaker → notes → Rank → Review → Copy ranks. Every action is a key press. Each target (Start room, Speech started,
Rank the room, Move down, Start again, Review and copy, Copy ranks) is reached with Tab. The script sets the place
Tab starts from (the main area, or the speaker code) and blurs focus before a one-key shortcut, because those keys
only work with nothing focused. On setup, room, rank and review it Tabs through every stop. It checks that each stop
shows a focus ring, that focus never lands on something hidden, and that Tab never gets stuck. Each line below is a
check that fails the walk, not just a printed note.

Both sizes, all five families: **no problem found in these screens.** The toast is not part of this walk. Its two
keyboard problems are listed above under "Open items for the core owner".

- **Focus order.** Each new screen puts focus on its title (setup from a ballot card puts it on the paste box). Tab
  then goes through the header, the screen head, and the content in reading order. Tab stops per screen: setup 13,
  room 28–42 (depends on the family and the size), rank 16, review 20.
- **Visible focus.** Every stop on those four screens showed a ring. A ring counts only if the element looks different
  focused and not focused (an outline, or a box-shadow it does not have otherwise). Limit: the script can tell a ring
  is there, not how easy it is to see. Ring contrast is covered by the token colors and axe's contrast rules.
- **Esc.** Esc closes the confirm sheet (focus goes back to the event that opened it), "Start the ranks again?" (focus
  goes back to Start again) and the palette (focus goes back where it was).
- **Shortcuts in the keyboard sheet.** With nothing focused, Space starts and stops the clock (the speaker then reads
  "Done"). For Impromptu, Space runs prep and "Speech started" moves on to the speech. Keys 1–3 pick speakers 1–3 in
  each family's room. Keys 4–8 pick speakers 4–8 in an 8-speaker room. In a 10-speaker room (Elim room rules), 9 then
  Enter, 1 0 then Enter, and 4 then Enter pick speakers 9, 10 and 4. Ctrl+K opens the palette.
- **Focus after an action.** Enter on Move down keeps focus on Move down. Enter on Copy ranks keeps focus on the same
  button, which then reads "Copy ranks again".
- **No trap.** Tab always got back to the start of the page on every screen walked.
